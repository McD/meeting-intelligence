# docs/

Working notes from the build, retained for design context. Not authoritative product documentation — the canonical install/usage docs live in the top-level `README.md`.

- **`ideation/`** — early "where could this go" exploration.
- **`brainstorms/`** — requirements documents written before each major phase.
- **`plans/`** — implementation plans, one per phase.

These read like a developer's scratchpad because that is what they are. They include first-name references, internal examples, and the specific decisions made along the way. They are kept in the repo because the design rationale ("why we built it this shape") is harder to recover from code than the code itself.

If you are evaluating the tool, start with the top-level `README.md`. If you want to understand a design choice, find the relevant plan in `plans/`.
